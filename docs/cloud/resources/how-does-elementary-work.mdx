## Cloud platform architecture 
Elementary connects directly to your data warehouse. It reads the information schema, the query history, and table metadata, and uses them to build lineage, run monitors, and track the health of every asset in scope.

If you use dbt, the Elementary dbt package adds a second source of context on top. The package runs inside your own dbt pipeline and writes test results, run results, and dbt artifacts to a schema it owns in the warehouse, which Elementary then syncs through the same connection.

You can also connect your code repository, so Elementary understands how your project is built — tags, owners, and which tables are part of it — and your BI tools, so it sees daily usage. Both are optional.

## How it works?
1. You connect an [environment](/cloud/environments) to your data warehouse, and choose the asset sources it contains — asset groups of databases and schemas, dbt projects, or both.
2. The cloud service reads metadata for those assets over an encrypted connection, and begins a backfill so monitors have a historical baseline.
3. If you use dbt, you install the Elementary dbt package and configure it to write to its own schema, the Elementary schema. The package writes test results, run results, logs and metadata there, and the cloud service syncs that schema.
4. All syncs run over an **encrypted connection** from a **static IP address** that you will need to add to your allowlist.
