The Elementary AI Agent automates the workflows that slow data teams down most: finding coverage gaps, triaging incidents, fixing broken pipelines, enriching metadata, and optimizing query performance.

It's one agent with a set of capabilities, each built for a specific workflow. You work with the same agent whether you open it from an incident, the catalog, the test coverage screen, or a Slack thread.

Every action the agent takes goes through a pull request or requires explicit confirmation. Your team stays in control of what gets merged.

## What the agent works from

The agent reasons over what Elementary already collects from your connected integrations, tied together through [lineage](/cloud/features/data-lineage/lineage):

- **Lineage** across your warehouse, dbt models, BI dashboards, and code, down to the column level
- **Test results and incidents** from dbt, Python, and cloud tests, including history and coverage gaps
- **Run and performance history** for models, tests, and orchestration jobs, including execution time and cost
- **Code changes** from your connected repository, such as recent commits and pull requests
- **Metadata** such as descriptions, tags, owners, and table usage

This is what lets the agent trace a failure back to the commit that caused it, or tell you which dashboards an incident affects, without you assembling the picture first.

<Note>The more integrations you connect, the more the agent can see. Lineage between dbt and BI tools, for example, only works when both are connected. See [integrations](/cloud/integrations/elementary-integrations).</Note>

## How it works

The agent runs on self-hosted models through Amazon Bedrock. No data leaves your environment, and all AI features are opt-in by default. Agent behavior is governed by AI policies you define: reviewable, adjustable, and aligned to your governance standards.
