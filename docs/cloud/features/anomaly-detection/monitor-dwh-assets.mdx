Elementary monitors all assets in your data stack, whether or not they were built by dbt. You select databases and schemas directly in your data warehouse, and Elementary syncs the tables and views in them — including those built by ETL tools, orchestrators, or SQL scripts.

Synced warehouse assets appear in the [lineage graph](/cloud/features/data-lineage/lineage) alongside your dbt models and sources, and support freshness and volume Cloud tests.

<Note>
Warehouse schemas are one of the [asset sources an environment can contain](/cloud/environments). A dbt project is the other, and an environment can hold either or both.
</Note>

## Syncing warehouse schemas

Add the databases and schemas you want to monitor as an asset source on the environment, in **Account settings > Environments**. Once synced, these assets appear in the side tree under the **DWH view**, alongside your dbt models and sources.

This lets you:
- Monitor tables built by ETL tools, orchestrators, or SQL scripts
- Gain visibility into your entire data warehouse inventory
- Apply the same monitoring and testing capabilities across every asset in the environment

<Warning>
Supported for **BigQuery**, **Snowflake**, and **Databricks**.
</Warning>

## Configuring tests on warehouse assets

Configure freshness and volume tests on synced assets from the **test configuration menu**. The process is the same as configuring tests on dbt models:

1. Navigate to the test configuration page
2. Select the warehouse asset you want to monitor
3. Choose either a **freshness** or **volume** test
4. Configure the test parameters as needed
5. Submit the test configuration

These tests run alongside your dbt tests, with the same alerting. Freshness and volume are available today, and more test types are coming.

## Lineage integration

Synced warehouse assets appear in the lineage view with their dependencies, including dependencies on assets in your dbt projects. Currently, **views** are fully supported in the lineage visualization, and **tables** support is coming soon.

This helps you:
- Understand how your dbt models depend on, or feed, assets built elsewhere
- Visualize the complete data flow across your warehouse
- Identify dependencies and impacts across your entire data ecosystem
